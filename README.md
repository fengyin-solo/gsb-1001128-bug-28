# 市政道路桥梁养护管理平台

覆盖道路巡查、桥隧定检、路面病害、交安设施、绿化管养、除雪防汛及养护工程管理的市政道桥全要素养护后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 区域切片发布单（绿化边界版本发布）

绿化边界确认后，地图切片、班组工作面/排班卡不能继续落在旧区域；撤回发布也不能留下
重复作业。为此把发布过程收敛为「区域切片发布单」，三段单向推进：

1. **确认审定附件**：绿线与临时围挡冲突时以「正式审定」附件为准（临时围挡不可选为
   审定结论），冲突段、越界段逐条留痕；历史修剪区间随切片携带，只保留不删除。
2. **核对切片责任**：审定后才生成切片，未审定不得跳级生成班组任务。切片与其他区域
   存量作业重叠时，先在重叠边界拆分责任（前段/后段分别指派班组），再逐片核对。
3. **执行发布**：切片、班组任务、地图引用**同一事务**落库，任一步失败整批回滚
   （复位整张旧图）；连接断开后重连从**首个未发布切片继续**。发布结论回写到**绿化台账、
   班组清单、地图待办**。

关键约束：

- 列表页、详情页、地图入口统一从「版本指针」取版本键（`区域编号@版本`），三处同源，
  杜绝区域版本错位。
- 发布键（`版本键:release`）**幂等**：并发发布按版本键只生效一次，重试不产生重复
  任务/引用；同一区域只允许一张在办发布单。
- 存量重叠区**先拆分责任、再按责任关系迁移**：旧切片/任务/地图引用按重叠段拆开，
  重叠段迁移到新版本与接管班组，残留段保留。
- 撤回整事务恢复旧区域（旧引用/旧任务/工作面/待办全部复位，迁移产物失效），重复
  撤回同样幂等。

接口（均在 `/api/green` 前缀下）：

| 方法 & 路径 | 说明 |
| --- | --- |
| `GET /regions/map` | 地图入口：生效绿线、班组工作面/排班卡、地图待办、区域版本 |
| `GET /regions/{code}/detail` | 详情页：台账 + 版本指针 + 审定附件候选 + 历史修剪区间 + 在办单 |
| `POST /publish-orders` | 发起发布单（同区域在办单自动复用） |
| `GET /publish-orders` / `/{id}` | 发布单列表 / 明细（含切片、任务、引用） |
| `POST /{id}/confirm-attachment` | 第一步：确认审定附件并生成切片 |
| `POST /{id}/slices/split` | 第二步：重叠区拆分责任 |
| `POST /{id}/slices/review` | 第二步：逐片核对切片责任 |
| `POST /{id}/publish` | 第三步：执行发布（幂等、可续发、整批事务） |
| `POST /{id}/withdraw` | 撤回发布，恢复旧区域 |

前端入口：绿化管养列表行内「区域切片发布」、区域详情页发起/继续按钮、侧边栏
「绿化地图」页。测试：`cd backend && python3 -m unittest discover -s tests`。
